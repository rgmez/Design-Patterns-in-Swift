# v1.0.0 — Pragmatic Swift Design Patterns

> - **Status:** Released
> - **Published:** 11 November 2026
> - **Tag:** [`v1.0.0`](https://github.com/rgmez/Design-Patterns-in-Swift/releases/tag/v1.0.0)
> - **Commit:** [`cde9d91`](https://github.com/rgmez/Design-Patterns-in-Swift/commit/cde9d912ba0331a0f81eb6d99a95de1477074a0d)

This first release turns the complete Gang of Four catalogue into an executable
Swift guide built around one rule:

> A pattern earns its place only when it solves a concrete problem more clearly
> than Swift's direct language and platform features.

## Highlights

- All 23 GoF patterns start from realistic app requirements rather than generic
  `Product`, `Creator`, or `Manager` examples.
- Every example begins with a direct Swift baseline and introduces a pattern
  only after observable pressure appears.
- One explicit no-pattern case keeps a pure `URLComponents` solution because
  Builder never earns its additional state.
- The package compiles every canonical example together and verifies behavior
  with Swift Testing.
- Every canonical guide includes trade-offs, nearby alternatives, a Mermaid
  diagram, an editorial header, and a concrete `When not to use it` section.
- `choose-swift-design-pattern` turns the catalogue's evidence gate into a
  reusable decision skill without treating pattern selection as a quota.

## Evidence-first decision model

Each teaching unit follows the same reviewable sequence:

1. Start with one real app requirement.
2. Implement the smallest direct Swift solution.
3. Add one credible product or integration change.
4. Measure coupling, invalid states, duplicated ownership, lifecycle risk, or
   resource cost.
5. Introduce the smallest boundary that moves that pressure to a clearer owner.
6. Record the new cost and the condition under which the direct solution still
   wins.

The pattern selects a responsibility boundary, not a mandatory class hierarchy.
The examples use value types, enums, closures, actors, `AsyncSequence`,
protocols, or classes only where the demonstrated ownership requires them.

## Example-hardening bonus track

Before release, ten focused stages tightened the catalogue's narrowest examples:

- historical sketches are explicitly separated from package-backed examples;
- Factory Method is compared with creation closures;
- Singleton no longer exports a public shared-storage accessor;
- Flyweight measures model-owned RGBA payload rather than claiming process RSS;
- Interpreter has an executable handoff to maintained parser infrastructure;
- Mediator proves that validation remains with its participants;
- Memento quantifies full-snapshot growth by content and history depth;
- Template Method is compared with higher-order Swift composition; and
- Visitor makes its cheap and expensive extension directions explicit.

The final hardening review retained only changes supported by executable or
structural evidence.

## Verification

The release was rebuilt from the repository root with warnings treated as
errors:

```sh
swift build -Xswiftc -warnings-as-errors
swift test -Xswiftc -warnings-as-errors
```

Repository-wide QA produced these results:

| Check | Result |
| --- | --- |
| Build | Passed without compiler warnings |
| Tests | 359 tests in 194 suites passed |
| Canonical README contract | 23 of 23 guides passed |
| Local links and images | 878 targets across 121 Markdown files resolved |
| Mermaid | 51 blocks passed structural validation |
| Visual assets | 24 headers retained the required 1672 × 941 dimensions |
| Approved visual reference | Adapter reference SHA-256 matched |
| Public Singleton API | No `shared` or `production` storage accessor exported |
| Historical material | Six documents and eight Swift sketches marked non-canonical |
| Private editorial workspace | `Editorial/` remained ignored and untracked |

## Known validation limits

- Mermaid CLI was unavailable, so diagram validation is structural rather than
  renderer-level.
- The pattern-selection skill is unchanged since its successful official
  validator run. Its frontmatter passed an independent YAML parse during final
  QA, but the current host Python could not rerun the official script because
  PyYAML was unavailable.
- Flyweight's exact byte figures describe model-owned RGBA elements, not total
  allocation, process RSS, framework caches, renderer copies, or GPU memory.
